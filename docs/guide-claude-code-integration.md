# Claude Code Integration Guide

How Shikomi works with Claude Code to scaffold, develop, and maintain macOS management scripts.

---

## What Shikomi Generates for Claude Code

When you pass `--claude y` (or answer "y" to the Claude Code prompt in the interactive wizard), Shikomi generates two files:

### CLAUDE.md

A project-level configuration file that gives Claude Code context about the repository. Contents are **template-aware** — they change based on choices made during scaffolding:

| Section | Always included | Varies by |
|---------|----------------|-----------|
| Project overview (name, type, generator version) | Yes | Template type |
| Shell conventions (bash 3.2+, shellcheck, shebang) | Yes | — |
| Versioning rules (use bump-version.sh) | Yes | — |
| Secret management method | Yes | 1Password / local / none |
| Security rules (.gitignore patterns, never commit secrets) | Yes | — |
| Extension Attribute guidelines | Only for EA templates | Template type |
| Session diary instruction | Yes | — |

### SESSION_DIARY.md

An initialized session tracking file with a first entry documenting what Shikomi generated:

```
### 2026-03-23 09:21 — Project scaffolded by Shikomi

**Investigated:** N/A (initial generation)
**Changed:** Project created with Shikomi v2.0.0
  - Generated: my_script.sh (Regular Script, v1.0.0)
  - Template: Regular Script
  - Mode: New Project (micro-repo)
**Decided:** Initial project structure
**Why:** Generated by Shikomi automated scaffolding
```

Every subsequent Claude Code session appends entries here, creating a complete history of decisions and changes.

## How Claude Code Uses Shikomi

### Prerequisites

1. Shikomi installed system-wide (`shikomi --version` works from any directory)
2. Claude Code has Bash tool access
3. Global `~/.claude/CLAUDE.md` includes Shikomi instructions (see below)

### Global Configuration

Add this to `~/.claude/CLAUDE.md` so Claude Code knows to use Shikomi across all projects:

```markdown
## Shikomi — macOS Script Scaffolding

When creating new macOS management scripts, Jamf Pro scripts, or Extension Attributes,
**always use Shikomi** (`shikomi` is installed system-wide) instead of writing boilerplate manually.

### Creating a new project (outside a git repo)
shikomi <script_name> --auto --claude y [additional flags]

### Creating a new script in an existing repo (monorepo mode)
shikomi <script_name> --auto --claude y --branch y [additional flags]
```

### The Workflow

Once configured, a typical interaction looks like this:

**You:** "Create a new Jamf script that installs Slack"

**Claude Code:**
1. Runs `shikomi install_slack --auto --claude y`
2. Reads the generated `install_slack.sh`
3. Replaces the `# TODO` section with actual installation logic
4. Tests with `shellcheck --severity=warning install_slack.sh`
5. Uses `bump-version.sh` if version changes are needed
6. Appends a session diary entry

The key insight: Claude Code handles scaffolding and logic in one session. The human reviews the result rather than writing from scratch.

## Non-interactive Mode Reference

Shikomi's `--auto` flag is what makes Claude Code integration possible. Without it, every `read -rp` prompt would hang the Bash tool.

### How --auto Works

- Skips all interactive prompts
- Uses sensible defaults for any flag not explicitly set
- Individual flags override specific defaults without requiring `--auto` for everything

### Flag Reference

| Flag | Values | Default with --auto | Purpose |
|------|--------|-------------------|---------|
| `--auto` | — | — | Enable non-interactive mode |
| `--template` | `regular` / `ea` | `regular` | Script template type |
| `--ea-suffix` | `y` / `n` | `y` | Append _ea to EA script names |
| `--scaffolding` | `y` / `n` | `n` | Per-script docs in monorepo |
| `--params-file` | path | — | Load Jamf parameters from JSON |
| `--no-params` | — | implied | Skip parameter collection |
| `--static-vars` | `1,2,4` / `none` | `none` | Standard macOS variables |
| `--branch` | `y` / `n` | `y` | Create feature branch (monorepo) |
| `--hooks` | `basic` / `enhanced` / `none` | `basic` | Pre-commit hook level |
| `--workflow` | `y` / `n` | `n` | GitHub Actions validation |
| `--deploy-workflow` | `y` / `n` | `n` | Jamf Pro deploy workflow |
| `--github` | `y` / `n` | `n` | Create GitHub repository |
| `--claude` | `y` / `n` | `n` | Generate CLAUDE.md + SESSION_DIARY.md |

### Parameters JSON File

For scripts that need Jamf parameters ($4-$11), create a JSON file:

```json
{
  "parameters": [
    {
      "index": 4,
      "label": "App Name",
      "secret": false,
      "default": "Slack"
    },
    {
      "index": 5,
      "label": "API Key",
      "secret": true,
      "storage": "1password",
      "op_vault": "Private",
      "op_item": "jamf-install-slack",
      "op_field": "api_key"
    }
  ]
}
```

Parsed with `plutil` (stock macOS) — no python3 or jq required.

## Common Scenarios

### New standalone script project

```bash
shikomi install_slack --auto --claude y
```

Creates a new directory with script, README, CHANGELOG, bump-version, .gitignore, pre-commit hooks, CLAUDE.md, and SESSION_DIARY.md. Git repo initialized and committed.

### New Extension Attribute

```bash
shikomi crowdstrike_version --auto --template ea --static-vars "4" --claude y
```

Creates an EA script with `<result>` output format, OS_VERSION as a static variable, and Claude Code configuration.

### New script in an existing monorepo

```bash
cd /path/to/my-scripts-repo
shikomi deploy_agent --auto --claude y --branch y
```

Creates the script in the current directory, creates a feature branch, and generates CLAUDE.md at the repo root (only if it doesn't already exist).

### Script with full CI/CD pipeline

```bash
shikomi patch_manager --auto --claude y --workflow y --deploy-workflow y --hooks enhanced --github y
```

Creates project with enhanced pre-commit hooks (9 checks), GitHub Actions validation workflow, Jamf Pro deploy-on-merge workflow, private GitHub repo, and Claude Code configuration.

### Script with Jamf parameters from config

```bash
# Create params.json first, then:
shikomi install_app --auto --params-file params.json --claude y --workflow y
```

## Monorepo vs Micro-repo Behavior

### Micro-repo (new project)

- CLAUDE.md generated in the project directory
- SESSION_DIARY.md generated in the project directory
- Both committed in the initial commit via `git add .`

### Monorepo (existing repo)

- CLAUDE.md generated at the **repo root** (not the script's subdirectory)
- SESSION_DIARY.md generated at the **repo root**
- **Neither file is overwritten** if it already exists — a message is printed and the existing file is preserved
- Both files are staged for commit alongside the new script

This means the first script you create with `--claude y` in a monorepo sets up the Claude Code configuration. Subsequent scripts reuse it.

## What the Generated CLAUDE.md Does NOT Include

The project-level CLAUDE.md focuses on **working within the repo**. It does not include:

- Instructions to use Shikomi for creating new projects (that belongs in `~/.claude/CLAUDE.md`)
- Personal preferences or workflow habits (those belong in global config or Claude memory)
- Git workflow instructions (those are in GITOPS_WORKFLOW.md)
- Jamf Pro API setup (that's in docs/reference-jamf-pro-api-setup.md)

This separation keeps each file focused and avoids duplication.

## Versioning with Claude Code

After Claude Code writes or modifies script logic, it should use bump-version.sh rather than manually editing version headers:

```bash
# From the project directory
./bump-version.sh patch "Added Slack installation logic"

# Or bump and commit in one step
./bump-version.sh patch "Added Slack installation logic" --commit

# In a monorepo, specify the script
./bump-version.sh install_slack.sh patch "Added installation logic" --commit
```

The generated CLAUDE.md includes this instruction, so Claude Code will follow it automatically.

## Troubleshooting

### Claude Code doesn't use Shikomi

Check that your global `~/.claude/CLAUDE.md` contains the Shikomi instructions. Claude Code reads this file at the start of every session.

### --auto mode hangs

This shouldn't happen — `--auto` skips all `read -rp` prompts. If it hangs, check:
- Is `pre-commit` installed? The `pre-commit install` command runs during scaffolding and requires the tool to be present. Use `--hooks none` to skip.
- Is `gh` CLI authenticated? Use `--github n` to skip GitHub repo creation.

### CLAUDE.md not generated

Verify you passed `--claude y`. In `--auto` mode, Claude scaffolding defaults to `n` (it's opt-in).

### CLAUDE.md skipped in monorepo

Expected behavior — if CLAUDE.md already exists at the repo root, Shikomi preserves it. Check the output for "CLAUDE.md already exists at repo root, skipping."

### plutil errors with --params-file

Ensure the JSON file is valid. Test with:
```bash
plutil -lint params.json
```
